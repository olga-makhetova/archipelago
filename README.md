# 🏝️ Архипелаг — симуляция экосистемы

Учебный проект на Java с графическим интерфейсом (Swing), моделирующий живую экосистему на системе островов —
архипелаге.

---

## 🌍 О проекте

**Архипелаг** — это симуляция, в которой на островах в реальном времени живут, охотятся, едят, размножаются и умирают
сотни существ. Каждый остров — это сетка клеток с собственной популяцией. Острова связаны между собой порталами, через
которые животные могут случайно перемещаться.

Приложение запускается со стартового окна, где пользователь задаёт **имя острова** и его **размер** (сетку N×M). После
нажатия «Создать» открывается новое окно с визуальной сеткой и логом событий. Можно создавать несколько островов
одновременно.

## 🐺 Сущности

| Категория     | Примеры                                                               |
|---------------|-----------------------------------------------------------------------|
| 🐺 Хищники    | Волк, Лис, Орёл и др.                                                 |
| 🐄 Травоядные | Лошадь, Корова, Утка, Гусеница и др.                                  |
| 🌿 Растения   | Растут каждый такт, периодически размножаются                         |
| 🌀 Порталы    | Телепортируют животное в случайную точку острова или на другой остров |

Все сущности отображаются в виде **эмодзи-иконок** на сетке острова.

---

## ⚙️ Как работает симуляция

Каждая живая сущность существует в **собственном потоке** (`ScheduledExecutorService`). На каждом такте:

- 🌿 **Растения** — растут, набирая вес; периодически порождают новые ростки в случайных клетках
- 🐾 **Животные** — перемещаются на соседнюю клетку, становятся голоднее
- 💥 **Столкновения** — разрешаются через `CollisionResolver` по следующей логике:
    - **Портал** → телепортация
    - **Травоядное + растение** → поедание
    - **Два животных одного вида** → возможность размножения
    - **Хищник + травоядное** → охота (хищник ест)
    - **Два хищника** → схватка (исход зависит от параметров)
    - **Два травоядных** → мирное сосуществование *(кроме утки и гусеницы — утка ест гусеницу)*

## 🧬 Архитектура и ООП

Проект демонстрирует ключевые концепции объектно-ориентированного программирования:

**Наследование и полиморфизм**

- Общая иерархия: `Entity` → `Living` → `Animal` → `Herbivorous` / `Predator`
- Поведение при столкновении определяется типом сущности через `instanceof` и полиморфные методы

**Паттерн Factory + рефлексия**

- Все сущности создаются через `EntityFactory` с использованием рефлексии (
  `Class.getDeclaredConstructor().newInstance()`) — добавить новый вид достаточно зарегистрировать в `EntityProperties`,
  не трогая фабрику
- `EntityFactory` находится в том же пакете, что и сущности: сеттеры начальных параметров (`setName`, `setWeight`,
  `setStrength` и др.) имеют package-private доступ и недоступны извне — инициализация возможна только через фабрику
- Конструкторы всех сущностей — protected, поэтому создать экземпляр напрямую (new) извне нельзя. Доступ к конструкторам
  есть только у наследников внутри пакета и у EntityFactory (через рефлексию).
- Каждое животное получает параметры с небольшим случайным разбросом (гауссово распределение), поэтому особи одного вида
  немного отличаются друг от друга

**Разделение данных и логики**

- Параметры каждого вида хранятся в `EntityDescription` — Java `record` с полями: вес, максимальный возраст, сила,
  плодовитость, скорость (`stepCount`) и др.
- `EntityProperties` организует их в иерархию Map-ов (`PREDATOR_MAP` → `ANIMAL_MAP` → `LIVING_MAP` → `ALL_MAP`),
  повторяя иерархию классов; сборка происходит через статические блоки `static {}`
- `stepCount` задаёт скорость жизни: кролик (`stepCount=5`) тикает в 5 раз чаще медведя (`stepCount=1`) — скорость
  существа выражена через частоту его потока
- Фабрика только читает данные из `EntityProperties` и применяет их — данные и логика создания строго разделены

**Многопоточность**

- Каждая сущность живёт в своём потоке (`ScheduledExecutorService`), что даёт настоящий параллелизм симуляции

**Разделение ответственности**

```
entity/     — иерархия существ (Animal, Plant, Herbivorous, Predator…)
model/      — описания и перечисления (Direction, EntityDescription)
service/    — логика (CollisionResolver, Island, NameGenerator, IconLoader)
ui/         — графика (IslandWindow, StartWindow, Cell)
```
